# Lua→Wasm Divergence Ledger

Companion to `docs/Lua-Wasm-Design-and-Test-Plan.md` §8.9.

**Rule: a divergence without a ledger row is a bug; a row without a test is a bug.**

Where the engines disagree (or any engine disagrees with C Lua 5.1, the
semantic authority), the ruling lives here. Rows record: what diverges,
why, the ruling, and the covering test or shim.

| # | What | Where | Why / ruling | Covered by |
|---|---|---|---|---|

| 14 | ABI reentrancy law (M5a callback machinery): an rt_* protected body that `luaD_call`s (rt_call fallback, metamethods in arith/len/cmp/concat/gettable) can re-enter the ABI — a wasm closure called through the adapter runs another rt_* before the outer body resumes, overwriting the shared argument statics. | 17 | When `...` is used, the compiler still reserves the `arg` local but never fills it (NeedsArg cleared at compile.go:1188, the local registered earlier) — `arg` inside such a function is the nil LOCAL, not the global. | fork compiler semantics | Matched by the backend (prologue skips rt_compat_arg exactly when NeedsArg is clear; R(np) nil-fills). ## M6 rows (2026-09-16 — CLI integration tests)

| # | Divergence | Where | Notes |
|---|---|---|---|
| 27 | Cumulative OP_CONCAT executions in one frame corrupt the run at ≥16: silent early exit with lua_main status 0 (output after the last completed concat is lost), staged garbage error bytes, or the row-10u nested-dispatch panic (`index out of range [5] with length 5` re-raised through enterWasm). Non-monotonic — with one module driven by an arg-supplied bound, n≤~32 died while n=80 died and n=90+ passed — layout-dependent, not a counter. No metamethods or callbacks involved: `for i=1,16 do t[i]="a".."b" end` suffices. First found by the `_cli-tests` grep clone over a 40+-line file. | runtime/rt_abi.c concat_body | **Fixed (2026-09-16, M6 triage):** `concat_body` popped the staging window with `top -= cc_n - 1`, leaving the residual result TValue on the Lua stack — a one-slot leak per rt_concat call (verified natively: `top - base` grew +1 per call). The crept top walked the stack past the frame until nested-dispatch machinery read garbage; the engine-side Go panic recover then discarded the whole event log (the "silent" mode). Every sibling body pops fully (gettable −2, settable −3); concat now does too (`top -= cc_n`). Native triage (`runtime/tests/rt_concattri_test.c`, ASan+UBSan) also caught a **GC-live use-after-free**: `rt_call` stepping the GC frees strings held only in ABI cells (cells are not roots — the documented row-11 contract; inert today because the engine stops the GC, a hazard for any GC-enabled mode; the test roots its operands). `_wasm-tests/concat16.lua` passes (skip removed); `_cli-tests` concatstress/grep2 promoted to check3. |
| 28 | pcall-caught core raises lose the position prefix on the value the script receives: interp returns `"chunk.lua:5: attempt to index..."` (stock C Lua prefixes the same way); the wasm path returned the bare `"attempt to index..."`. | 29 | io.write's buffered tail was lost in both wasm-guest engines: the drivers return without libc `exit()`, so wasi-libc's atexit stdout flush never runs and only the first buffered line reached the host capture file (a >4KB write masked it by forcing flushes). | 30 | Multiple assignment to locals evaluated sequentially, not simultaneously: `compileAssignStmtRight` passed the target local's register as the RHS compile destination, so `a, b = b, a+b` clobbered `a` before the second RHS read it (fib degenerated to powers of 2; `x, y = y, x` lost the swap). Found by `_cli-tests` fib vs clua. | compile.go compileAssignStmtRight | Fixed (2026-09-16): a local target whose old value a later RHS still reads (or that is assigned twice) evaluates into a temp window slot instead of direct-writing the live register; everything else keeps the original codegen. `_wasm-tests/masgn01.lua` pins the interp≡wasm lowering; `_cli-tests` fib runs against C Lua every `make test`. |
| 31 | calc-shaped programs die on the wasm backend in layout-dependent modes: silent rc=0 with no output at all, a memory-fault trap at a garbage address (runtime-built heap bytes read as a pointer), or an infinite hang before the first print.
