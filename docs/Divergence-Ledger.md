# Divergence Ledger

The continuation of glasm's ledger (`docs/glasm-history/Lua-Wasm-Divergence-Ledger.md`,
rows 1–105, frozen at the carve): new rows number from 106. The law is
inherited unchanged — **the interpreter is byte-exact with stock C Lua
5.5.1; a divergence without a ledger row is a bug, and a row without a
covering test is a bug.** Where this engine disagrees with stock (or
with the glasm-blob contracts it inherited), the ruling lives here.

Rows record: what diverges, why, the ruling, and the covering test.

| # | Divergence | Where | Why / ruling | Covered by |
|---|---|---|---|---|
| 106 | **KEEP — N2: SetMx retired.** The library's `SetMx` armed a process-wide `ReadMemStats` poller that `os.Exit(3)`'d the host when RSS crossed the limit — a library killing its embedder's process. Glasm could live with that posture (one engine per wasm host, the exit was the alarm); an embed library cannot. | `state.go` (deleted with N2), `membudget.go` (replacement), `cmd/glua/glua.go` (`-mx` flag removed) | **Ruling:** the process-kill memory cap is deleted from the API surface; the per-VM accounted budget (row 107) is the mechanism, raised as an ordinary pcall-catchable error inside the faulting VM. Standalone `glua` runs unbudgeted. | host budget tests (`host/sandbox_test.go`); the golden corpus (every leg) — no behavior change, `SetMx` no longer exists |
| 107 | **KEEP — N2: memory budget accounting is an estimate.** Stock wraps its allocator (`l_alloc`) so every `luaM_` allocation counts against `lua_setmemlimit` exactly; Go allocations cannot be interposed. | `membudget.go`, `table.go` (creation/growth charges), `_vm.go` (concat fold, per-instruction check), `stringlib.go`/`tablelib.go` (builder charges) | **Ruling:** the budget is accounted at the big seams — table creation/growth at the per-slot estimates `collectgarbage("count")` has always charged (16/array slot, 48/hash slot, 64 header), the string builders at their result sizes — and is never refunded (a monotone high-water gauge). Overshoot between the crossing charge and the next raise is bounded by one builder result; the per-instruction boundary check (beside the deadline check) caps everything else. Unbudgeted VMs (`memLimit == 0`, the default) pay one field load per instruction and nothing else. | `host/usedbytes_test.go` (monotone, closed→0, fresh-VM drop); `host/sandbox_test.go` TestMemoryBudget{Concat,Gmatch,Tconcat} spins |
| 108 | **KEEP — N2: opt-in sandbox surfaces.** `WithGlobalsProtection`, `WithStdLibs`/`SafeStdLibs`/`AllStdLibs`, `WithMaxCoroutines` are embed options, off by default — stock Lua semantics are unchanged for any VM that does not opt in (glasm blob rows 94/95 posture). Text deltas vs the glasm-blob contracts: (a) the glasm host tests carried the chunkname's `=` in error prefixes (`=test:1:`) — the native engine renders stock `luaO_chunkid`, which strips a leading `=` (`test:1:`); (b) `rawset(_G, …)` under protection raises prefixed in both the caught and uncaught shapes natively (the glasm row-94 bare-under-pcall form was a C-VM execution artifact with no compiled-frame analog); (c) `coroutine.create` past `WithMaxCoroutines` raises `too many coroutines` — a new engine text, no stock analog (the cap is an embed feature). | `host/protection.go`, `host/host.go`, `host/vm.go`, `tablelib.go` (baseRawSet guard), `_state.go` (setField guard, MaxCoroutines) | **Ruling:** all three surfaces are opt-in; the guard/bypass seam split is: bytecode write paths + `rawset` guard (`setField`/`setFieldString`/`baseRawSet`), `LState.RawSet`/`LTable.RawSet*` stay raw as the host staging seam (KEYS/ARGV stage through it, guest-writable by contract — the glasm walk order). | `host/sandbox_test.go` (byte-text battery, allows, pcall, off-by-default, staging, pooled rerun, stdlib selection, coroutine cap+release) |
| 109 | **KEEP-OPEN — package.path default carries the 5.1-era install root.** `LuaLDir = "/usr/local/share/lua/5.1"` (and the `!\\lua` Windows form) bake stock 5.1's install path into `package.path`'s default; stock 5.5.1 uses its 5.5 root. `package.cpath` is empty (no C loader — pure Go). | `config.go` | **Ruling:** open. Only visible when `package` opens (`AllStdLibs` or an explicit `WithStdLibs` entry); the default `SafeStdLibs` posture never opens it, and the golden corpus resolves its requires through `./?.lua` so the root never matches. Fixing it means choosing an install-path story for a library with no installer — deferred until an embedder needs `require`. | none (open) |
